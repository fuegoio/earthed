## Container images

Planetary publishes images to GitHub Container Registry on every push to `main` and every release:

| Image | Registry                        |
| ----- | ------------------------------- |
| API   | `ghcr.io/fuegoio/planetary-api` |
| Web   | `ghcr.io/fuegoio/planetary-web` |

Tags: `latest` (main branch), `1.2.3` / `v1.2.3` (release), `1.2` (minor), `1` (major), `sha-<short>` (commit).

Both containers run as a non-root user (`uid 10001`). The API listens on port 8080, the web app on port 3000.

## Quick start with Docker Compose

```yaml
services:
  postgres:
    image: postgres:16-alpine
    environment:
      POSTGRES_USER: planetary
      POSTGRES_PASSWORD: <db-password>
      POSTGRES_DB: planetary
    volumes:
      - pgdata:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U planetary"]
      interval: 5s
      timeout: 3s
      retries: 10

  api:
    image: ghcr.io/fuegoio/planetary-api:latest
    ports:
      - "8080:8080"
    environment:
      LIMEN_SECRET: <32-byte-secret>
      PLANETARY_DATABASE_URL: postgres://planetary:<db-password>@postgres:5432/planetary?sslmode=disable
      PLANETARY_BASE_URL: https://api.your-domain.com
      PLANETARY_WEB_URL: https://your-domain.com
    depends_on:
      postgres:
        condition: service_healthy
    healthcheck:
      test: ["CMD", "wget", "-q", "--spider", "http://localhost:8080/api/v1/health"]
      interval: 30s
      timeout: 5s
      retries: 3

  web:
    image: ghcr.io/fuegoio/planetary-web:latest
    ports:
      - "3000:3000"
    environment:
      PLANETARY_API_URL: http://api:8080
      NEXT_PUBLIC_PLANETARY_API_URL: https://api.your-domain.com
    depends_on:
      api:
        condition: service_healthy

volumes:
  pgdata:
```

Start:

```bash
docker compose up -d
```

Run database migrations on first start:

```bash
docker compose exec api /app/planetary --migrate
```

`PLANETARY_API_URL` is the server-side URL the web container uses to reach the API over the Docker network. `NEXT_PUBLIC_PLANETARY_API_URL` is baked into the browser bundle and must be publicly reachable.

## Environment variables

### API

| Variable                         | Default                                                                   | Description                                               |
| -------------------------------- | ------------------------------------------------------------------------- | --------------------------------------------------------- |
| `LIMEN_SECRET`                   | **required**                                                              | 32-byte secret for session signing. `openssl rand -hex 16` |
| `PLANETARY_DATABASE_URL`         | `postgres://planetary:planetary@localhost:5432/planetary?sslmode=disable` | PostgreSQL connection string                              |
| `PLANETARY_HTTP_ADDR`            | `:8080`                                                                   | HTTP listen address                                       |
| `PLANETARY_BASE_URL`             | `http://localhost:8080`                                                   | Public URL of the API (used for auth redirects)           |
| `PLANETARY_WEB_URL`              | `http://localhost:3000`                                                   | Public URL of the web frontend                            |
| `PLANETARY_LOG_FORMAT`           | `pretty`                                                                  | Log format: `pretty` or `json`                            |
| `PLANETARY_POLLING_FREQUENCY`    | `60s`                                                                     | How often the scheduler checks for due feeds              |
| `PLANETARY_BATCH_SIZE`           | `100`                                                                     | Feeds processed per scheduler tick                        |
| `PLANETARY_WORKER_POOL_SIZE`     | `5`                                                                       | Concurrent feed-processing workers                        |
| `PLANETARY_HTTP_CLIENT_TIMEOUT`  | `20s`                                                                     | Timeout for fetching a single feed                        |
| `PLANETARY_HTTP_CLIENT_MAX_BODY` | `15728640`                                                                | Max feed body size in bytes (15 MB)                       |
| `PLANETARY_CLEANUP_FREQUENCY`    | `24h`                                                                     | How often to run entry cleanup                            |
| `PLANETARY_ENTRY_MAX_AGE_DAYS`   | `60`                                                                      | Entries older than this are eligible for cleanup          |
| `PLANETARY_DISABLE_SCHEDULER`    | (unset)                                                                   | Set to any non-empty value to disable the scheduler       |

### Web

| Variable                        | Default                 | Description                                                  |
| ------------------------------- | ----------------------- | ------------------------------------------------------------ |
| `PLANETARY_API_URL`             | `http://localhost:8080` | Server-side API URL (reachable from the container)           |
| `NEXT_PUBLIC_PLANETARY_API_URL` | `http://localhost:8080` | Client-side API URL (reachable from the browser)             |

## Reverse proxy

Neither service terminates TLS directly. Put both behind a reverse proxy (nginx, Caddy, Traefik).

Example nginx configuration:

```nginx
server {
    listen 443 ssl;
    server_name your-domain.com;

    ssl_certificate /path/to/cert.pem;
    ssl_certificate_key /path/to/key.pem;

    location /api/ {
        proxy_pass http://localhost:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location / {
        proxy_pass http://localhost:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

## Database backup

All feeds, entries, folders, and feed lists are in PostgreSQL. Back it up regularly.

```bash
# Create a backup
docker compose exec postgres pg_dump -U planetary planetary > backup.sql

# Restore from a backup
cat backup.sql | docker compose exec -T postgres psql -U planetary planetary
```

Schedule `pg_dump` with a cron job and store backups off-site for automated backups.
