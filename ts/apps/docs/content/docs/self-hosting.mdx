## Official container images

Planetary publishes container images to GitHub Container Registry on
every push to `main` and every tagged release:

| Image | Registry |
| --- | --- |
| API | `ghcr.io/fuegoio/planetary-api` |
| Web | `ghcr.io/fuegoio/planetary-web` |

Images are tagged as follows:

- `latest` — tracks the `main` branch
- `1.2.3` / `v1.2.3` — semantic version tags
- `1.2` — minor version tag
- `1` — major version tag
- `sha-<short>` — commit SHA tag

Pull an image:

```bash
docker pull ghcr.io/fuegoio/planetary-api:latest
docker pull ghcr.io/fuegoio/planetary-web:latest
```

## Quick start with Docker Compose

The fastest way to self-host Planetary is a single `docker-compose.yml`
with PostgreSQL, the API, and the web frontend:

```yaml
services:
  postgres:
    image: postgres:16-alpine
    environment:
      POSTGRES_USER: planetary
      POSTGRES_PASSWORD: <db-password>
      POSTGRES_DB: planetary
    volumes:
      - pgdata:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U planetary"]
      interval: 5s
      timeout: 3s
      retries: 10

  api:
    image: ghcr.io/fuegoio/planetary-api:latest
    ports:
      - "8080:8080"
    environment:
      LIMEN_SECRET: <32-byte-secret>
      PLANETARY_DATABASE_URL: postgres://planetary:<db-password>@postgres:5432/planetary?sslmode=disable
      PLANETARY_BASE_URL: https://api.your-domain.com
      PLANETARY_WEB_URL: https://your-domain.com
    depends_on:
      postgres:
        condition: service_healthy
    healthcheck:
      test: ["CMD", "wget", "-q", "--spider", "http://localhost:8080/api/v1/health"]
      interval: 30s
      timeout: 5s
      retries: 3

  web:
    image: ghcr.io/fuegoio/planetary-web:latest
    ports:
      - "3000:3000"
    environment:
      PLANETARY_API_URL: http://api:8080
      NEXT_PUBLIC_PLANETARY_API_URL: https://api.your-domain.com
    depends_on:
      api:
        condition: service_healthy

volumes:
  pgdata:
```

Start everything:

```bash
docker compose up -d
```

Run migrations (first time only):

```bash
docker compose exec api /app/planetary --migrate
```

The web frontend is reachable at `http://localhost:3000` and the API at
`http://localhost:8080`.

`PLANETARY_API_URL` is used server-side (the web container reaching the
API container over the Docker network). `NEXT_PUBLIC_PLANETARY_API_URL`
is baked into the client bundle and must be reachable from the browser.

## Running containers manually

If you prefer not to use Compose, run each container individually.

API:

```bash
docker run -p 8080:8080 \
  -e LIMEN_SECRET=<32-byte-secret> \
  -e PLANETARY_DATABASE_URL=postgres://user:pass@db-host:5432/planetary?sslmode=require \
  ghcr.io/fuegoio/planetary-api:latest
```

Web:

```bash
docker run -p 3000:3000 \
  -e PLANETARY_API_URL=http://api-host:8080 \
  -e NEXT_PUBLIC_PLANETARY_API_URL=https://api.your-domain.com \
  ghcr.io/fuegoio/planetary-web:latest
```

Both containers run as a non-root user (`uid 10001`). The API listens on
port 8080, the web app on port 3000.

## Building from source

If you prefer to build the images yourself instead of using the
pre-built ones, both Dockerfiles are multi-stage and produce minimal
runtime images:

```bash
# API (from repo root)
docker build -f go/api/Dockerfile -t planetary-api .

# Web (from ts/ directory)
docker build -f ts/apps/web/Dockerfile -t planetary-web ts/
```

## Environment variables

### API

| Variable | Default | Description |
| --- | --- | --- |
| `LIMEN_SECRET` | **required** | 32-byte secret for session signing. Generate with `openssl rand -hex 16`. |
| `PLANETARY_DATABASE_URL` | `postgres://planetary:planetary@localhost:5432/planetary?sslmode=disable` | PostgreSQL connection string. |
| `PLANETARY_HTTP_ADDR` | `:8080` | HTTP listen address. |
| `PLANETARY_BASE_URL` | `http://localhost:8080` | Public URL of the API (used by Limen for auth redirects). |
| `PLANETARY_WEB_URL` | `http://localhost:3000` | Public URL of the web frontend. |
| `PLANETARY_LOG_FORMAT` | `pretty` | Log format: `pretty` or `json`. |
| `PLANETARY_POLLING_FREQUENCY` | `60s` | How often the scheduler checks for feed updates. |
| `PLANETARY_BATCH_SIZE` | `100` | Number of feeds to process per scheduling cycle. |
| `PLANETARY_WORKER_POOL_SIZE` | `5` | Number of concurrent feed-processing workers. |
| `PLANETARY_HTTP_CLIENT_TIMEOUT` | `20s` | Timeout for fetching remote feeds. |
| `PLANETARY_HTTP_CLIENT_MAX_BODY` | `15728640` | Max feed body size in bytes (15 MB). |
| `PLANETARY_CLEANUP_FREQUENCY` | `24h` | How often to run entry cleanup. |
| `PLANETARY_ENTRY_MAX_AGE_DAYS` | `60` | Entries older than this are eligible for cleanup. |
| `PLANETARY_DISABLE_SCHEDULER` | (unset) | Set to any non-empty value to disable the feed scheduler. |

### Web

| Variable | Default | Description |
| --- | --- | --- |
| `PLANETARY_API_URL` | `http://localhost:8080` | Server-side API URL (must be reachable from the container). |
| `NEXT_PUBLIC_PLANETARY_API_URL` | `http://localhost:8080` | Client-side API URL (must be reachable from the browser). |

## Reverse proxy

In production, put both services behind a reverse proxy (nginx, Caddy,
Traefik) that handles TLS termination. Neither the API nor the web app
serve HTTPS directly.

Example nginx configuration:

```nginx
server {
    listen 443 ssl;
    server_name your-domain.com;

    ssl_certificate /path/to/cert.pem;
    ssl_certificate_key /path/to/key.pem;

    location /api/ {
        proxy_pass http://localhost:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location / {
        proxy_pass http://localhost:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

## Database backup

Your PostgreSQL database holds all feeds, entries, folders, and feed
lists. Back it up regularly.

Create a backup:

```bash
docker compose exec postgres pg_dump -U planetary planetary > backup.sql
```

Restore from a backup:

```bash
cat backup.sql | docker compose exec -T postgres psql -U planetary planetary
```

For automated backups, schedule `pg_dump` with a cron job and store
backups off-site (e.g., an S3 bucket or other object storage).
