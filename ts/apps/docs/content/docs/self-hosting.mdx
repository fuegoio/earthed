## Docker

The API ships with a multi-stage Dockerfile that produces a static
binary. Build from the repository root:

```bash
docker build -f go/api/Dockerfile -t planetary-api .
```

Run the container:

```bash
docker run -p 8080:8080 \
  -e LIMEN_SECRET=<32-byte-secret> \
  -e PLANETARY_DATABASE_URL=postgres://user:pass@db-host:5432/planetary?sslmode=require \
  planetary-api
```

The container runs as a non-root user (`planetary`, uid 10001) and
listens on port 8080.

## Docker Compose

For local development, a `docker-compose.yml` in `go/api/` runs
PostgreSQL only. For a full self-hosted setup, create a compose file
that includes both PostgreSQL and the API:

```yaml
services:
  postgres:
    image: postgres:16-alpine
    environment:
      POSTGRES_USER: planetary
      POSTGRES_PASSWORD: <db-password>
      POSTGRES_DB: planetary
    volumes:
      - pgdata:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U planetary"]
      interval: 5s
      timeout: 3s
      retries: 10

  api:
    build:
      context: .
      dockerfile: go/api/Dockerfile
    ports:
      - "8080:8080"
    environment:
      LIMEN_SECRET: <32-byte-secret>
      PLANETARY_DATABASE_URL: postgres://planetary:<db-password>@postgres:5432/planetary?sslmode=disable
      PLANETARY_BASE_URL: https://api.your-domain.com
      PLANETARY_WEB_URL: https://your-domain.com
    depends_on:
      postgres:
        condition: service_healthy
    healthcheck:
      test: ["CMD", "wget", "-q", "--spider", "http://localhost:8080/api/v1/health"]
      interval: 30s
      timeout: 5s
      retries: 3

volumes:
  pgdata:
```

Start everything:

```bash
docker compose up -d
```

Run migrations:

```bash
docker compose exec api /app/planetary --migrate
```

## Environment variables

| Variable | Default | Description |
| --- | --- | --- |
| `LIMEN_SECRET` | **required** | 32-byte secret for session signing. Generate with `openssl rand -hex 16`. |
| `PLANETARY_DATABASE_URL` | `postgres://planetary:planetary@localhost:5432/planetary?sslmode=disable` | PostgreSQL connection string. |
| `PLANETARY_HTTP_ADDR` | `:8080` | HTTP listen address. |
| `PLANETARY_BASE_URL` | `http://localhost:8080` | Public URL of the API (used by Limen for auth redirects). |
| `PLANETARY_WEB_URL` | `http://localhost:3000` | Public URL of the web frontend. |
| `PLANETARY_LOG_FORMAT` | `pretty` | Log format: `pretty` or `json`. |
| `PLANETARY_POLLING_FREQUENCY` | `60s` | How often the scheduler checks for feed updates. |
| `PLANETARY_BATCH_SIZE` | `100` | Number of feeds to process per scheduling cycle. |
| `PLANETARY_WORKER_POOL_SIZE` | `5` | Number of concurrent feed-processing workers. |
| `PLANETARY_HTTP_CLIENT_TIMEOUT` | `20s` | Timeout for fetching remote feeds. |
| `PLANETARY_HTTP_CLIENT_MAX_BODY` | `15728640` | Max feed body size in bytes (15 MB). |
| `PLANETARY_CLEANUP_FREQUENCY` | `24h` | How often to run entry cleanup. |
| `PLANETARY_ENTRY_MAX_AGE_DAYS` | `60` | Entries older than this are eligible for cleanup. |
| `PLANETARY_DISABLE_SCHEDULER` | (unset) | Set to any non-empty value to disable the feed scheduler. |

## Reverse proxy

In production, put the API behind a reverse proxy (nginx, Caddy, Traefik)
that handles TLS termination. The API itself does not serve HTTPS.

Example nginx configuration:

```nginx
server {
    listen 443 ssl;
    server_name api.your-domain.com;

    ssl_certificate /path/to/cert.pem;
    ssl_certificate_key /path/to/key.pem;

    location / {
        proxy_pass http://localhost:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

## Web frontend

The web frontend is a Next.js app with a standalone Docker build:

```bash
docker build -f ts/apps/web/Dockerfile -t planetary-web ts/
```

Run the container:

```bash
docker run -p 3000:3000 \
  -e PLANETARY_API_URL=http://api-host:8080 \
  -e NEXT_PUBLIC_PLANETARY_API_URL=https://api.your-domain.com \
  planetary-web
```

`PLANETARY_API_URL` is used server-side (must be reachable from the
container). `NEXT_PUBLIC_PLANETARY_API_URL` is used client-side (must be
reachable from the browser).

Alternatively, build and run from source:

```bash
cd ts
pnpm install
pnpm build
pnpm start
```

## CI/CD

The repository includes GitHub Actions workflows (`.github/workflows/go.yml`
and `.github/workflows/ts.yml`) that build and push Docker images to GitHub
Container Registry. On push to `main`:

- API: `ghcr.io/<owner>/planetary-api:latest`
- Web: `ghcr.io/<owner>/planetary-web:latest`
- Docs: `ghcr.io/<owner>/planetary-docs:latest`

## Database backup

Your PostgreSQL database holds all feeds, entries, categories, and feed
lists. Back it up regularly.

Create a backup:

```bash
docker compose exec postgres pg_dump -U planetary planetary > backup.sql
```

Restore from a backup:

```bash
cat backup.sql | docker compose exec -T postgres psql -U planetary planetary
```

For automated backups, schedule `pg_dump` with a cron job and store
backups off-site (e.g., an S3 bucket or other object storage).
