---
title: Feed Lists
description: Curate, share, and follow collections of feeds.
---

Feed lists are curated, shareable collections of feeds. You build a list
from feed URLs, make it public, and other users can discover, follow, or
import all its feeds into their own subscriptions.

A feed list stores feed URLs and a metadata snapshot (title, site URL) —
it does not reference a specific user's subscriptions, so a list is
portable and can be shared with anyone.

## Create a feed list

```bash
curl -X POST http://localhost:8080/api/v1/feed-lists \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer pla_your-token" \
  -d '{"title":"Best engineering blogs","description":"A curated set.","is_public":true}'
```

Set `is_public` to `true` so others can discover and follow the list. You
can change this later with `PATCH /api/v1/feed-lists/{listId}`.

## Add feeds to a list

Only the list owner can add feeds. Provide the feed URL; a title is
optional but recommended so the list reads well before import.

```bash
curl -X POST http://localhost:8080/api/v1/feed-lists/1/feeds \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer pla_your-token" \
  -d '{"feed_url":"https://blog.golang.org/feeds/posts/default","title":"The Go Blog"}'
```

Adding the same feed URL twice is a no-op (the existing entry is
returned). Remove a feed with
`DELETE /api/v1/feed-lists/{listId}/feeds/{itemId}`.

## Discover and follow

List public feed lists created by other users:

```bash
curl http://localhost:8080/api/v1/feed-lists/discover \
  -H "Authorization: Bearer pla_your-token"
```

Follow a public list:

```bash
curl -X POST http://localhost:8080/api/v1/feed-lists/1/follow \
  -H "Authorization: Bearer pla_your-token"
```

You cannot follow your own list, and you cannot follow a private list.
Lists you follow are returned by `GET /api/v1/feed-lists/followed`.

Unfollow a list with `DELETE /api/v1/feed-lists/{listId}/follow`.

## Import a list's feeds

Following a list keeps it bookmarked but does not subscribe you to its
feeds. To subscribe to every feed in a list at once:

```bash
curl -X POST http://localhost:8080/api/v1/feed-lists/1/import \
  -H "Authorization: Bearer pla_your-token"
```

The response reports how many feeds were newly imported, how many you
already subscribed to (skipped), and any that failed:

```json
{
  "imported": 8,
  "skipped": 2,
  "failed": 0
}
```

Importing is idempotent — running it again only creates subscriptions for
feeds you don't already have.

## Update a feed list

Change the title, description, or visibility of a list:

```bash
curl -X PATCH http://localhost:8080/api/v1/feed-lists/1 \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer pla_your-token" \
  -d '{"title":"Updated title","is_public":false}'
```

Only the list owner can update or delete a list.

## Delete a feed list

```bash
curl -X DELETE http://localhost:8080/api/v1/feed-lists/1 \
  -H "Authorization: Bearer pla_your-token"
```

Returns 204 No Content on success.

## Visibility

A feed list is visible to:

- its owner,
- anyone following it, and
- everyone, if it is public.

`GET /api/v1/feed-lists/{listId}` returns the list (with its feeds,
follow status, and owner email) to any user who can see it.

## Data model

### Feed List

| Field | Type | Description |
| ----- | ---- | ----------- |
| `id` | int | List ID |
| `user_id` | int | Owning user ID |
| `title` | string | List title |
| `description` | string | List description (omitted if empty) |
| `is_public` | bool | Whether the list is discoverable |
| `created_at` | string | Creation timestamp |
| `updated_at` | string | Last update timestamp |

### Feed List Item

| Field | Type | Description |
| ----- | ---- | ----------- |
| `id` | int | Item ID |
| `feed_list_id` | int | Parent list ID |
| `feed_url` | string | Feed URL |
| `title` | string | Feed title (metadata snapshot) |
| `site_url` | string | Site URL (metadata snapshot, omitted if empty) |
| `created_at` | string | Creation timestamp |

See [API Reference](/docs/api-reference#feed-lists) for the full endpoint
list.
