title: Getting Started
description: Run Sunred locally, create an account, subscribe to a feed, and read entries.
---

## Prerequisites

- [Go](https://go.dev/dl/) 1.25 or later
- [Node.js](https://nodejs.org/) 20+ with [pnpm](https://pnpm.io/) 10+
- [Docker](https://docs.docker.com/get-docker/) (for PostgreSQL)

## 1. Start PostgreSQL

```bash
cd go/api
make db-up
```

This starts a PostgreSQL 16 container on port 5432 with database `sunred`, user `sunred`, password `sunred`.

## 2. Configure environment

Create a `.env` file in `go/api/`:

```bash
SUNRED_DATABASE_URL=postgres://sunred:sunred@localhost:5432/sunred?sslmode=disable
SUNRED_BASE_URL=http://127.0.0.1:8080
SUNRED_WEB_URL=http://localhost:3000
```

`SUNRED_BASE_URL` must use `127.0.0.1` (not `localhost`) because RFC 8252
rejects `localhost` in OAuth redirect URIs. The API derives the callback URL
from `SUNRED_BASE_URL` and redirects `127.0.0.1` callbacks to `localhost` so
the session cookie (host-only on `localhost`) is shared across ports 3000
and 8080.

Users log in with their own AT Proto handle — typically a Bluesky account or an
account on a personal PDS. No PDS setup is required. See
[Identity & sync](/at-proto) for how login and data sync work.

## 3. Run migrations

```bash
cd go/api
make migrate
```

## 4. Start the API server

```bash
cd go/api
make run
```

Verify it is running:

```bash
curl http://localhost:8080/v1/health
# {"status":"ok"}
```

## 5. Create an account

Sunred uses AT Proto identity — there is no email/password signup. Start the
web frontend (step 8), click **Continue with snrd.social** to log in or sign up
through the default PDS, or use **Login with a different handle** to sign in
with an existing AT Proto handle (e.g. your Bluesky account).

See [Identity & sync](/at-proto) for how login and data sync work.

## 6. Create an API token

API tokens are used for the CLI, curl, and scripts. Create one with the session cookie from the previous step:

```bash
curl -X POST http://localhost:8080/v1/tokens \
  -H "Content-Type: application/json" \
  -b cookies.txt \
  -d '{"label":"my-token"}'
```

Save the `token` value from the response — it starts with `pla_` and is shown only once.

## 7. Subscribe to a feed

```bash
curl -X POST http://localhost:8080/v1/feeds \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer pla_your-token-here" \
  -d '{"feed_url":"https://blog.golang.org/feeds/posts/default"}'
```

You can also pass a website URL — Sunred discovers the feed automatically from `<link rel="alternate">` tags.

## 8. Read entries

```bash
curl "http://localhost:8080/v1/entries?limit=10" \
  -H "Authorization: Bearer pla_your-token-here"
```

## 8. Start the web frontend

```bash
cd ts
pnpm install
pnpm dev
```

The web app is at `http://localhost:3000`. The login page shows a
**Continue with snrd.social** button (the default PDS, configurable via
`NEXT_PUBLIC_SUNRED_DEFAULT_PDS`) and a **Login with a different handle**
option for existing AT Proto accounts.

## 9. Try the CLI

```bash
cd go/cli
make build
./sunred config set base_url http://localhost:8080
./sunred config set token pla_your-token-here

./sunred feeds list
./sunred entries list
./sunred-tui   # interactive TUI
```

See [CLI](/cli) for the full command reference.
